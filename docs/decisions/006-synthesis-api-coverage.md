# 006: Synthesis API coverage

**Status:** accepted and implemented (phase 3a of the implementation plan). "Findings" below records
what implementation changed or left open.

## Context

Under ADR 005, scripts use the native `IPatcherState` API. Four parts of it still fail closed or differ from a
native patcher:

- nested records
- autogenerated settings
- `state.AssetProvider`, including archives listed in the game's INI file
- persistent FormKey allocation

The goal is native behaviour for each, without giving the worker any new authority.

## Decision

### Settings and persistence are data, not queries

Settings files and persistence files are small, and the host can name them from Synthesis's arguments
(`--ExtraDataFolder`, `--PersistencePath`). They go to the worker inline in `Start`, and the Synthesis code in the
worker reads them unchanged.

What comes back is untrusted:

- Settings never come back.
- The persistence file comes back in `Submit`. The host checks every entry against the new records it accepted,
  then writes the file itself.

Settings types must also exist in the trusted patcher, because Synthesis's GUI reflects over it. A settings
source is therefore held to a stricter policy than the script: data-only classes (auto-properties, constant
initial values and Synthesis settings attributes, with no code). It is compiled into both assemblies.

### Assets are the one lazy query

A Data folder can hold hundreds of thousands of loose files, and a patcher typically reads a few hundred. So the
worker asks for them one at a time (`AssetRequest` → `AssetReply`), rather than getting all of them up front.

The host resolves each request in trusted code:

- It checks the path is a normalized Data-relative path.
- It checks the manifest's `Assets` patterns allow it.
- It checks the resolved full path is still under Data and isn't a reparse point.
- It counts the request against the budgets for request count and total bytes.

The worker gets back a read-only duplicated handle, or `missing`. Under MO2 the host runs inside the virtual file
system, so it sees what the game sees.

The only extra information the worker learns is whether allowed paths exist. Those are game assets, and the
worker has no way to send anything out except the output plugin, which is validated field by field.

The worker hides the query behind `BrokeredFileSystem`, so Synthesis's own `GameAssetProvider` builds
`state.AssetProvider` unchanged. Archives, including INI-listed ones, are shared up front as they are today.

Synthesis finds the game INI, which lists archives no plugin is named after, under My Documents, and that does
not resolve inside the AppContainer (see "Findings"). So the host looks the INI up the way Synthesis does
(`IniPathLookup`) and shares it inline, naming it in `Start.GameIniPath`. The worker then hands the program a
copy of the pipeline's state whose asset provider is built as Synthesis builds it, with the INI path injected
(`IniArchives`). The pipeline still writes and disposes its original state. Before the program runs, the worker
checks by reflection that every public state member other than `AssetProvider` is the pipeline's own. A
Synthesis update that adds state therefore fails the run rather than hiding something from the program.

### Nested records are diffed per record, with child groups left out generically

Mutagen models cells, worldspaces and topics as records that contain groups of child records. If the parent were
diffed with its full equals mask, adding one reference would show up as a change to the whole cell.

The committer therefore:

- Diffs each nested record on its own under the usual `Type.Field` policy.
- Diffs each parent with the fields that hold major records left out. Those fields are found by their type, not
  listed by name.
- Applies records through `GetOrAddAsOverride` on a context, which builds the parent chain.

This keeps the rule that record interpretation uses Mutagen's generated code and never names a record type.

### Removal is granted per record type

A record in the patch mod that the output leaves out is a removal. In a Synthesis patch mod, removing an
override reverts to the version below it, and removing a record the patch added deletes it. Both are ordinary
patcher operations (`state.PatchMod.Remove<T>(formKey)`), so they are allowed, but only for the record types in
the manifest's `Removable` list, which is empty by default. The committer:

- rejects a removal whose type is not removable. Removing a parent removes its children, and each child's type
  must be removable too;
- rejects deleting a record that any record in the output still links to. Reverting an override cannot break
  a link, because the version below it remains;
- reports each removal as a `RecordChange` with `IsRemoved`, counts it against `MaxRecords`, and applies it
  after the additions, children first.

### Export options: the worker's plugin is an intermediate

The worker's plugin only carries the patch back to the host; the host's own Synthesis run writes the real
output. So options that only shape the real output are the host's alone, and options that change how plugins
are read are the worker's too:

- **`--Localize`** is removed from the worker's arguments (`SynthesisInputs.WorkerArguments`), and the worker
  turns localization off after the program runs, since a localized source plugin would otherwise turn it on.
  The intermediate keeps its strings embedded. A localized source's strings files (`Strings\<name>_*`) are
  shared, so the worker reads its text.
- **`--SplitIfMaxMastersExceeded`** stays, because Synthesis also uses it on read, to merge a split source
  plugin (`<name>_2.esp`...). The split parts of a source are shared. A patch that needs more masters than one
  plugin can hold comes back as parts in `Submit.OutputPlugins`, and the host reads them as one mod
  (`ModFactory.ImportMultiFileGetter`).
- **`--TargetLanguage` and `--UseUtf8ForEmbeddedStrings`** stay. The host's `ModCodec` reads the output and
  writes baselines with the same language and encoding (`PluginFormat`), so text is read back as written.

### Versions

Protocol version 3 adds `AssetRequest`/`AssetReply`, `Submit.Persistence` and the split parts in
`Submit.OutputPlugins`. Manifest schema 3 adds `Assets`
and `Settings`.

## Consequences

- Patchers that read assets must declare the patterns they read. That makes the declaration part of the review,
  like `Writable`.
- The session is no longer strictly request-free: the host has to serve asset requests while waiting for
  `Submit`, under the same timeout.
- Settings sources become a second agent input that reaches trusted code. The only thing that makes this safe is
  the data-only policy, so its tests must be thorough.

## Findings

- **Allocator commit.** Synthesis disposes its state at the end of the pipeline run, after writing the plugin,
  and the allocator commits `<PatcherName>.txt` on dispose. The worker returns that file in `Submit`. The
  host's own allocator never commits, because the host never allocates: it copies records with the FormKeys
  the worker gave them. The host raises `NextFormID` past those FormKeys, with or without persistence, so
  later patchers in the group do not reuse them.
- **My Documents does not resolve in the sandbox.** `Environment.GetFolderPath(MyDocuments)` returns an empty
  string inside the AppContainer (the folder cannot be verified, and passing `USERPROFILE` does not help).
  Without help, Mutagen finds no game INI, and `state.AssetProvider` sees only archives named after plugins,
  not INI-listed ones such as the vanilla `Skyrim - *.bsa` files. The host-shared INI and the worker's
  `IniArchives` hook fix this. A sandbox test reads a file from an archive that only the INI lists.
- **Shared-up-front files are never requested.** Mutagen probes for missing plugins (implicit masters such as
  `Update.esm`). The worker answers plugin, archive and strings paths locally as missing, because the host
  already shared every such file that exists.
- **Settings have no default-folder fallback.** Synthesis reads settings only from `--ExtraDataFolder`, and uses
  the defaults when the file is missing. The host does the same.
- **Sub-object fields in equals masks.** Generated equals masks expose sub-object entries (such as
  `PlacedObject.Placement` and `Weapon.Data`) as properties rather than fields. The diff read only fields, so
  changes to those went unseen. It now reads both, and a test covers it.
- **Embedded strings were read with the default encoding.** Before `PluginFormat`, a run with
  `--UseUtf8ForEmbeddedStrings` would have read the worker's UTF-8 names as Windows-1252 and copied the garbled
  text into the patch. A test covers it now.
- **Localized text after a change.** A changed record is copied from the intermediate, which holds text in the
  target language only. When the real output is localized, a changed record's other languages are not carried
  over. Unchanged records are untouched.
- **Archive fixture.** `BsaFixture` writes an uncompressed Skyrim SE archive (v105). Tests read files from a
  plugin-named archive and an INI-listed one, and check that a loose file wins over an archived one.
