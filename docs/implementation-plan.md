# SafeSynthesis — Implementation Plan

## Status (September 2026)

**Architecture change:** see ADR 005. Scripts are native Synthesis patch functions with the full Mutagen API.
The worker runs the real Synthesis pipeline over brokered read-only plugin handles, and the host validates the
output plugin field by field using Mutagen's generated code. The hand-written SDK and typed-edit protocol
described below (`Sdk`, `RecordKey`, `FieldCatalog`, `ReplaceField`) were removed. The phase and test structure
below still applies.

### Scale measurements (September 2026)

From `ScaleTests` (category `Scale`, run manually) in the real sandbox. The program is a general leveled-list
merge plus a pass that rescales every reference in one cell. Each list is overridden by 6 plugins.
`SAFEPATCH_SCALE_PLUGINS` and `SAFEPATCH_SCALE_RECORDS` set the size.

| Plugins | Records changed | Session | Host commit | Worker peak | Output |
| --- | --- | --- | --- | --- | --- |
| 500 | 7,006 (2,006 lists, 5,000 refs) | 5.4 s | 2.3 s | 118 MiB | 4 parts, 1.1 MiB |
| 2,000 | 7,006 | 6.9 s | 2.8 s | 145 MiB | 17 parts, 1.2 MiB |
| 1,000 | 70,006 (20,006 lists, 50,000 refs) | 166 s | 57 s | 585 MiB | 9 parts, 11 MiB |

- Loose assets cost one round trip each: 2,000 requests take about 1.2 s.
- The limits need no change. The 2 GiB worker memory limit, the 512 MiB frame limit and per-request asset
  serving all leave wide margins.
- The large run is dominated by Mutagen, not SafePatch:
  - The program's own merge loop took 83 s of the worker's 85 s for 20,000 lists (profiled in process), as it
    would in a native patcher.
  - References all in one cell are quadratic, because `GetOrAddAsOverride` scans the cell's child list. The
    native patcher pays this once in the worker. The host pays it twice more: once building baselines and once
    applying. At 50,000 references in one cell that was 15 s and 22 s of the commit.
  - Avoiding it would need per-type code, which the conventions rule out. Real cells hold far fewer references.

## Context

`Synthesis_MCP_design.md` describes SafeSynthesis: agent-authored C# patch algorithms that run in an OS-sandboxed worker, return a validated patch transaction, and are applied to `state.PatchMod` by a trusted wrapper that Synthesis builds and runs. The repo contains only that design. This plan turns it into an ordered build with a project structure that can grow without tangling, keeps each piece as simple as it can be, and keeps it **testable without Skyrim, Synthesis, or the sandbox wherever possible**.

Decisions already made:
- **Runtime first.** Build the sandbox/IPC/`LVLI` vertical slice before the authoring service. MCP comes last as a thin adapter.
- **Publisher = the user's own repos.** No third-party distribution or trust story (design §12.6). Publisher signing stays optional.
- **xUnit** for tests.

## Guiding principles (apply to every phase)

1. **Pure core, thin edges.** Validation, policy, proposal building, query paging, and diffing are plain functions over plain data, with no I/O, Mutagen, or processes. Mutagen, Win32, pipes, and Synthesis sit in edge projects behind a small number of interfaces.
2. **An interface only when there's a second implementation**, and a test fake counts as one. Planned seams:
   - `IRecordSource`: the read model. Real: Mutagen-backed. Fake: in-memory dictionary.
   - `IWorkerLauncher`: returns a duplex `Stream` to a running worker. Real: AppContainer + Job Object. Test: in-process worker over a pipe pair.
   - `IPatchTarget`: applies validated edits. Real: `ISkyrimMod`. Fake: records calls.
   - `IRecordAdapter`: one per record type (starting with `LVLI`). It handles projection, field descriptors, mutation, and domain invariants.
3. **No DI container.** One hand-written composition root in `SafePatch.Synthesis` (and later one in `SafePatch.Mcp`).
4. **Dependency direction is enforced by a test.** An architecture test reads the project references and fails if a core project references Mutagen, Synthesis, Roslyn, or Win32 interop.
5. **Fail closed.** Every edge returns or throws a typed error. There is no "continue without sandbox" path in production code. The in-process launcher lives only in a test-support project.
6. **Keep it simple until a profile says otherwise.** The wire format is length-prefixed frames carrying strict `System.Text.Json` payloads (source-generated, `UnmappedMemberHandling.Disallow`, `MaxDepth`, max frame size). A binary codec or local mirror waits until measurement shows a need (design §6, §10).

## Solution layout

```
SafeSynthesis.sln
Directory.Build.props        # nullable, TreatWarningsAsErrors, LangVersion, deterministic, lock files
Directory.Packages.props     # central package management, pinned versions
global.json                  # pinned SDK
src/
  SafePatch.Sdk/             # agent-facing API: ISafePatch, IPatchContext, RecordId, FieldId, LeveledItem DTOs. Zero deps.
  SafePatch.Protocol/        # wire messages, frame codec, bounded parser, session state machine. → Sdk
  SafePatch.Worker.Core/     # IPatchContext impl over a Stream, proposal builder, payload loading via AssemblyLoadContext. → Sdk, Protocol
  SafePatch.Worker/          # exe: ~20-line Main that calls Worker.Core. Nothing else.
  SafePatch.Host/            # preflight, manifest/policy, query service over IRecordSource, broker session,
                             #   validation pipeline, diff/report. → Sdk, Protocol. NO Mutagen.
  SafePatch.Skyrim/          # Mutagen edge: IRecordSource over ILinkCache/load order, LVLI adapter, IPatchTarget over ISkyrimMod.
  SafePatch.Sandbox.Windows/ # IWorkerLauncher: AppContainer/LPAC, Job Object, handle allow-list, env scrub.
  SafePatch.Synthesis/       # SafePatchHost.Run(state, ...) entry point + composition root.
  SafePatch.Compiler/        # (phase 2) pinned Roslyn compile + semantic policy walker.
  SafePatch.Generator/       # (phase 2) emits trusted patcher repo from template/.
  SafePatch.Authoring/       # (phase 5) service layer: get_record, test_patch, package_…
  SafePatch.Mcp/             # (phase 5) MCP adapter over Authoring. No logic of its own.
template/                    # pinned trusted Synthesis project template (Program.cs, csproj w/ globbing off)
tests/
  SafePatch.Protocol.Tests/  SafePatch.Host.Tests/  SafePatch.Worker.Core.Tests/
  SafePatch.Skyrim.Tests/    # builds tiny in-memory SkyrimMod fixtures with Mutagen; no game install
  SafePatch.Sandbox.Tests/   # [Trait("Category","Sandbox")] Windows-only; runs probe suite inside real worker
  SafePatch.Compiler.Tests/  # allowed/forbidden source corpus
  SafePatch.Architecture.Tests/
  SafePatch.EndToEnd.Tests/  # [Trait("Category","Synthesis")] drives real Synthesis CLI on fixture load order
  SafePatch.TestSupport/     # InMemoryRecordSource, InProcessWorkerLauncher, fixture builders, golden-diff helper
```

This deliberately merges some of the design's §4 projects. Contracts is split into **Sdk** (what agent code sees) and **Protocol** (wire). **Host** is split so the validator and broker are testable without Mutagen. Projects are created only in the phase that needs them.

## Test strategy

| Layer | How it's tested | Needs |
| --- | --- | --- |
| Protocol codec/parser | Unit + table-driven malformed frames, size/depth limits; later a fuzz harness (SharpFuzz) | nothing |
| Validator, policy, diff | Pure unit tests: `(proposal, snapshot, policy) → ValidationResult`; golden JSON for reports | InMemoryRecordSource |
| Host ↔ Worker session | Full session with `InProcessWorkerLauncher`, a sample `ISafePatch`, and a fake target | nothing external |
| LVLI adapter / commit | Mutagen round-trip: build mod in memory → project → mutate → write → re-read | Mutagen only |
| Sandbox | Probe suite executed inside the real contained worker; asserts every denial | Windows, `Category=Sandbox` |
| Compiler policy | Corpus of `.safe.cs` files that must pass or fail with a specific diagnostic code | Roslyn |
| End-to-end | Synthesis CLI runs generated patcher against fixture plugins; same-group visibility | Synthesis, `Category=Synthesis` |

The default `dotnet test` runs the first five rows and finishes in seconds. CI runs everything on a Windows runner.

## Phases

### Phase 0: Feasibility spikes (design §11 phase 0, §12.1–3)
Throwaway code lives in `spikes/`. Its findings go into `docs/decisions/NNN-*.md`.
1. Minimal Synthesis patcher that sets one `LVLI` field. Record the pinned Synthesis/Mutagen versions and the TFM, then set `global.json` and `Directory.Packages.props` to match.
2. .NET worker launched under AppContainer, then LPAC, from the patcher, including under MO2 VFS. Write the ADR choosing between them.
3. Anonymous-pipe echo between the host and the contained worker.
4. Same-group visibility: confirm which `state` objects include earlier patchers' edits (§12.2), and whether `PatchMod` can be detached or swapped (§12.3).

**Exit:** the design's phase-0 gate is met, and the ADRs are recorded.

### Phase 1: Vertical slice (LVLI merge)
Build it in this order, where each step is green before the next:
1. Scaffolding: sln, `Directory.*.props`, `Sdk`, `Protocol`, `TestSupport`, and the architecture test.
2. `Sdk`: `RecordId`, `FieldId`, `LeveledItem`/`LeveledEntry` immutable records, `IRecordQueries` (`WinningOverrides` paged, `GetOverrideChain`, `ResolveLink`), and `IPatchProposal.ReplaceField`.
3. `Protocol`: message types (`Hello`, `Query`, `Reply`, `SubmitTransaction`, `Result`), frame codec, limits, and the session state machine.
4. `Host`: manifest and policy parsing, query service over `IRecordSource`, a validator pipeline of small `IValidationRule`s (policy → preconditions → structural → domain → diff), and the broker session.
5. `Worker.Core`: context implementation and proposal builder. Its session test uses `InProcessWorkerLauncher`.
6. `Skyrim`: Mutagen `IRecordSource`, the LVLI adapter, and `IPatchTarget`, with round-trip tests.
7. `Sandbox.Windows`: productionize the phase-0 launcher and add the probe suite.
8. `Synthesis`: `SafePatchHost.Run`, the composition root, and fail-closed exceptions.

**Exit:** the design's phase-1 gate. A two-override fixture merges, a following patcher sees the result, and each malformed-proposal fixture leaves `PatchMod` untouched.

### Phase 2: Trusted generator + compiler
`Compiler` covers the pinned reference pack, the semantic allow-list walker, and emitting the artifact plus its hash. `Generator` copies `template/` and adds `payload/`. It uses an explicit `Compile` list and never compiles `.safe.cs`.
**Exit:** the design's phase-2 gate.

### Phase 3: Hardening
IPC and transaction fuzzing, the negative security matrix (§11 test matrix, items 2–3), and a determinism test (run twice, byte-equal semantic diff).

### Phase 3a: Synthesis API coverage
The goal: a script that uses any part of `IPatcherState` behaves as it would in a native patcher, or fails closed
with a clear error. The design is in ADR 006. The work items land in this order: A and B need no protocol change;
C moves the protocol and manifest to v3, and D builds on it.

These facts come from the pinned sources (Synthesis 0.36.6, Mutagen 0.54.4):
- `state.AssetProvider` is a `GameAssetProvider` over `DataDirectoryAssetProvider` and `ArchiveAssetProvider`,
  both built on the pipeline's `IFileSystem` (our `BrokeredFileSystem`). Its API is only `Exists`, `TryGetSize`
  and `TryGetStream`.
- Persistence: `--PersistencePath`/`--PatcherName` install `TextFileSharedFormKeyAllocator` over the same file
  system when the folder has its marker file. The allocator reads every `*.txt` file there and, on `Commit()`,
  writes `<PatcherName>.txt`.
- `SetAutogeneratedSettings<T>` reads its file relative to `--ExtraDataFolder` through the same file system.
  Synthesis's GUI finds `T` by reflecting over the patcher assembly, so `T` must exist in the trusted patcher.

**A. Nested records** (`Mutagen` only)
- The committer finds each output record's context: `EnumerateMajorRecordContexts` on the output, and
  `TryResolveContext` in the link cache for the original.
- Nested records (placed objects, navmeshes, landscape, dialogue responses) are diffed on their own under the
  same `Type.Field` policy.
- Parents (`Cell`, `Worldspace`, `DialogTopic`) are diffed without their child-group fields. `RecordDiff` finds
  those fields generically, as fields holding major records or groups of them, so no record type is named. A
  parent written only to hold a changed child counts as unchanged.
- A new nested record needs a parent in the load order or the output, and `CanCreate` for its type. An existing
  record may not move to a different parent.
- Apply with `context.GetOrAddAsOverride(patchMod)`, which creates the parent chain, then copy the validated
  record in. `ModCodec.RoundTrip` writes nested baselines inside their parents.
- Tests (`Mutagen.Tests`, extending `PluginFixture`):
  - moving a placed object when `PlacedObject.Placement` is writable, and the rejection when it isn't
  - adding a placed object to an existing cell
  - a cell header change that isn't allowed
  - an exterior cell, and the worldspace's persistent cell
  - a dialogue response
  - a rerun that makes no changes

**B. Autogenerated settings** (`Compiler`, `Generator`, `Worker.Core`, `Synthesis`)
- The agent may supply a settings source: classes with public auto-properties and constant or `new()` initial
  values.
  - Allowed types: primitives, strings, enums, lists and arrays of these, `FormLink<T>`/`IFormLinkGetter<T>`,
    `ModKey`, and nested settings classes.
  - Allowed attributes: only those from `Mutagen.Bethesda.Synthesis.Settings`.
  - No methods, constructors, static state or property bodies.
  - A new `SettingsPolicyChecker` enforces this (diagnostics SP03xx).
- The script opts in natively with `public static Lazy<TSettings> Settings = null!;`. `PatchProgram.Load` finds
  the field, and `WorkerRuntime` calls `SetAutogeneratedSettings(nickname, path, out lazy)` and assigns it before
  the run.
  - Manifest v3 adds `Settings: { Type, Nickname, Path }`.
- The generator compiles the same settings source into the trusted patcher. It goes in the template's explicit
  `Compile` list as `Settings.cs`, only after the policy check passes. The template calls
  `SetAutogeneratedSettings` with that type, so Synthesis's settings GUI works.
- `SynthesisInputs.Plan` shares `<ExtraDataFolder>/<path>` inline. (Synthesis has no default-folder fallback,
  so neither does the host.) The report records `SettingsSha256`.
- Tests:
  - settings sources that must pass and that must fail (a method, a static field, a forbidden type)
  - an in-process run whose result depends on a setting
  - a generated patcher that builds (`Build`)
  - a Synthesis CLI run with a `settings.json` (`Synthesis`)

**C. Asset provider** (`Protocol`, `Host`, `Worker.Core`, `Synthesis`; protocol v3)
- Manifest v3 adds `Assets`: Data-relative glob patterns such as `meshes/**/*.nif`. It is empty by default, which
  means no asset access.
- A new message pair, `AssetRequest(Path)` → `AssetReply(Handle?, Contents?, Exists)`, is allowed only between
  `Start` and `Submit`.
- Worker: `BrokeredFileSystem` resolves unregistered paths under Data on demand. `Exists`, `OpenRead` and
  `FileInfo.Length` send an `AssetRequest` and cache the reply. Synthesis's own `GameAssetProvider` is untouched,
  so `state.AssetProvider` stays native. Archives are already shared as handles.
- Host: a new `AssetBroker` in `Host`, pure over an `IAssetSource` seam (a real Data folder, and a test fake).
  - It normalizes the path and rejects rooted paths, `..`, `:`, device names, and trailing dots or spaces.
  - It matches the path against `Assets` and checks that the resolved full path is still under Data.
  - It opens the file with `FileShare.Read`, refuses reparse points, and shares the handle read-only.
  - `PatchPolicy` gains `MaxAssetRequests` and `MaxAssetBytes`. Exceeding either rejects the run.
- INI-listed archives: Mutagen looks for the game INI under My Documents, which the AppContainer cannot
  resolve. The host shares the INI, and the worker gives the program an asset provider that reads it
  (ADR 006, "Assets are the one lazy query").
- Tests:
  - `AssetBroker` units: traversal, alternate data streams, rooted paths, a pattern miss, budgets, reparse
    points
  - a session test with the fake source
  - an in-process run reading a loose `.nif` and a BSA-packed file through `state.AssetProvider`
  - a sandbox probe: an asset outside the patterns is refused, and the direct path is still denied

**D. FormKey persistence** (`Worker.Core`, `Synthesis`, `Mutagen`; uses protocol v3)
- Spike first: find where the pipeline calls `IFormKeyAllocator.Commit()` (it isn't in Synthesis's own code; the
  mod write is the likely place), and how patchers in one group share the folder. Record the findings in ADR 006.
- `SynthesisInputs.Plan` shares the marker file and every `*.txt` in `PersistencePath` inline, so the allocator
  runs natively in the worker.
- `Submit` gains `Persistence`, the worker's `<PatcherName>.txt` after the commit.
- The host treats that file as untrusted. The committer checks every entry against the accepted new records:
  - It must map an accepted new record's EditorID to that record's FormKey.
  - It must agree with existing entries, with no ID claimed by another patcher.
  - Its FormKey must be in the patch's ModKey.
- The host then writes `<PatcherName>.txt` itself, using the temp-then-replace method, and raises
  `NextFormID` past every ID used.
- Tests:
  - two runs give a new record the same FormKey
  - a tampered file is rejected
  - an ID claimed by another patcher is rejected
  - without persistence, new IDs don't collide with earlier patchers' records in the group

**Exit:** each item's tests pass, and ADR 005's limitations list is empty.

### Phase 4: CACO fixture
Fetch `LeveledListUtilities.cs` from the CACO_Patcher repo, port representative cases as `.safe.cs`, and compare them against golden diffs. Record any missing adapter fields as backlog items.

### Phase 5: Authoring service + MCP
`Authoring` exposes the §9 operations as plain methods over `IRecordSource` and a load-order snapshot, so tests call them directly. `Mcp` is a thin adapter using the official C# MCP SDK. Each tool maps 1:1 to an `Authoring` method, and it has no write route. Additional record adapters are added here, each with its own round-trip fixture set.

### Phase 6: Release hardening
Per design §11.
